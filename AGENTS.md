## Learned User Preferences

- Day-to-day work goes on the `develop` branch; the repo keeps only `main` and `develop`. Commit/push to `develop`, then merge to `main` for releases.
- Plan-first workflow: produce a written plan file, then execute it with the prompt "Implement the plan as specified, it is attached for your reference. Do NOT edit the plan file itself." Do not regenerate todos that the plan already created.
- After substantive UI/app changes, always finish by deploying with `npm run deploy:preview` and reply with the Hosting channel URL (the `…--preview-…web.app` link), not just the default site URL. Resend pre-assessment links use production `APP_HOST` (default `*.web.app`), not preview channels — run production hosting deploy when validating `/remote` for real clients. For AXIS report number/layout changes, first show a local example on real report data (dev server `/preview/sample-report`) and wait for approval before deploying anything.
- UI taste is minimalist and Claude-inspired: **clarity over cleverness** — the next move should always be obvious; push back on busy or “clever” UI. No boxes-in-boxes, no overlay paragraphs, restrained rounding, pill-shaped quick actions, full-bleed work surfaces; side menus (assessment sidebar, mobile sheets) must always collapse/close on navigation and never stick open over the work. Computer-vision overlays (MediaPipe pose landmarks, etc.) must feel professional and trustworthy — restrained dot size and thin lines, never the heavy default look. **Client AXIS report** must be **presentable for a live post-assessment debrief**: professionally presented (InBody-like document feel), scannable, no placeholders or walls of text; every figure (hero, session tables, roadmap pace, protein/macros) must come from **one calculation** and be explainable in the room — protein **2.2 g/kg body weight on a cut** (~1 g/lb), not skeletal muscle and not 2.6 g/kg calculator presets; **goal-first** and sex-aware (findings secondary to stated goals — show we can get them there; female peer group; muscle-gain must not get cut advice). The report is a PT-onboarding **aha** / no-obligation conversion tool over one plan block (currently **16 weeks**): non-signups still keep the roadmap as a lead-magnet giveaway; joining clients reassess each block. It should make **4–5 sessions a week feel like a no-brainer without lying** (realistic ranges; 4–5 sessions let the coach hit each body part twice a week and burn more calories), but **never promise "you'll be at X by Y"** — no end-state target weights or landing values beyond what the client asked for (the healthy-weight floor is a backstop, never a target). Drop decorative pillar graphics (body-comp bars, muscle maps, metabolic icons); keep a **filled radar** whose colour tracks the score (green high → amber → red low; not multi-coloured sides). Hero is **score left + radar right** (document full-bleed on mobile and tablet — side gutter only on desktop; side-by-side on tablet+, stack on mobile) plus a short **2–3 sentence** results summary (age/sex peer placement, best finding, 2–3 areas to improve) — no "Focus this block", not five competing sections. Pillar score badges use the same **traffic-light score colours** (not a colour per pillar). First assessments must **never** show "vs last" / "improved since last time" (re-saves of the same assessment are not a prior). Section bands use **alternating backgrounds** — grey/banded sections are **report-only**; coach surfaces (client profile) stay white cards on workspace grey (quieter `rounded-lg`, not the report’s document layout). Client profile uses the same filled score-coloured radar as the AXIS report; pillar snapshots are name + one traffic-light score (no duplicate icons). **Lifestyle** is a boxed table: label + value + status chip + a **short tip per factor** (`LifestyleFactorsCard`; sleep timing/duration/environment; stress 2–3 strategies; nutrition calories/protein/minimally processed/fruit-veg-fibre; hydration all fluids not water-only; activity 8,000 benefits start / aim 10,000; caffeine 8h) — table-style gridlines and zebra rows; **do not collect alcohol** (omit entirely; never score); **no lifestyle icons**. **Movement** shows only patterns that need work — not three long lists or gap analysis — and shares one section band with **Posture** (same background; posture is image + feedback per view plus a short summary, not a table, and is not repeated under Movement). Measurable pillars use a **single-path Now | 1 month | 16 weeks** gap (one training dose — plan default sessions, typically 4 or 5 if they already train 5+); **drop 3 / 4 / 5 session friction** (no pricing-table comparison). The **16-week plan** section is one **SMART goal + how** per **stated client goal** (Weight loss, Build muscle, Improve fitness, etc. — not one row per assessment pillar), all visible at a glance — **not** a metrics/copy table and **not** coach hand-entry UI (**no Everfit branding**, no copy button). Fuel strip shows pace and macros. Body comp pace and strength/fitness % (absolute change underneath) come from the same physiology rates (slower for lean clients, women, advanced lifters; loss ≤1% body weight/week); extra sessions count as **extra calorie burn**, not a harsher diet. **Do not invent extra metric rows** outside the assessed set — body weight, body fat, muscle, fitness, and the four strength tests (upper-body strength and endurance, lower-body strength and endurance, grip strength, core strength). Strength lives in the **strength pillar** as professional client-facing numbers (no coach copy button). Tape measurements belong on a **collapsible sex-matched figure** (original male and female silhouette figures — no paid stock art, no fibre-level muscle plate; female clients get the female figure), **not** in the session tables; the collapsed state must look expandable. Plus a soft CTA to work with the coach. Do **not** include a self-guided / "starting on your own" takeaway under the roadmap. **Do not reference ARC** in the client report for now. Empty client surfaces must not show archetype or pillar scores before real assessment data. Healthy metrics outside the client’s goals should be congratulated or lightly maintained — not pushed to elite performance targets; projections must **never take anyone past optimal** (e.g. don't force a lower resting HR), yet clients already in great shape who state a goal still get realistic progress toward it (never "you can't build muscle / get leaner"). Numbers must hold up for **every population** (weights, heights, sexes, activity levels) so the system can be trusted. Client/PWA copy stays plain-language (**Fitness level**, not raw VO₂/HRR): **clear not clever**, every line answers **"so what, why should I care?"**, no clinical jargon (no "anterior pelvic tilt"), and **no em dashes anywhere** in client-facing copy. Posture expanded view explains **why it matters, what causes it, and how we'll fix it** (strengthen X, loosen Y, 2–3 named moves with a one-line how-to, no sets/reps) — no muscle-map graphics. Coach daily loop is **assess → AXIS report**; push back on duplicate surfaces, pre-flight complexity, and anything that isn’t that loop. Remote pre-assessment welcome: one **Start** CTA, duration hint in brackets under the button, two short motivating lines — no numbered step lists or boxy landing chrome. Live movement capture on iPad: **observe-then-tag** chip pads (large targets, optional “looks good”, summary after the set) — not stacked dropdowns while the client is mid-rep.
- **New-client baseline:** Keep **name / email / phone** (and DOB/gender as needed); **remove PAR-Q and medications** from One Assess — they are collected in other systems; **remove alcohol** from collection and report. **Pre-assessment** is lifestyle/goals (+ optional posture) via coach link or in-studio; **physical assessment** in app (**P3 → P4 → P5 → P2 → P7**, `STUDIO_PHYSICAL_PHASE_ORDER` — fitness first for a true seated resting HR; P4 is gym-floor movement only; P5 strength; P2 is the private-room block last — analyzer, then tape + posture photos, immediately before Results). No in-app consultation product or booking funnel — consultations happen outside One Assess. **Walk-in studio:** intake in studio → physical order above. **Send link first** is the long-term main path: client prefills at home → studio shows **pre-assessment review only if partial** → physical (skip intake when remote complete; skip duplicate studio posture if four remote views set); coach picks up at fitness. **Entry flow:** every global "New assessment" button is new-client-only (name + email → straight into first capture step); existing-client reassessments start from the client profile, never the global buttons — but reassessment UI is deferred until the baseline assess-and-report loop is solid. Collect `clientGoals` on lifestyle + remote `full` scope; do **not** collect `goalDeadline` or pain severity. Track activity level (and steps), not primary training styles. Tape measurements are mandatory alongside analyzer body comp (keep shoulders and calves; **do not collect neck**) but **not mixed into body-comp scoring** — tape is for progress (“biceps grew, waist came in”). Analyzer confirm stays **slim**: coach confirms weight / BF% / muscle (+ visceral/WHR if present); **do not** use analyzer BFM, BMR, or segmental lean to “improve” AXIS — macros stay **Mifflin**. When **weight-loss** is a goal, AXIS year weight is floored at a healthy adult size (BMI ~21 male / ~20 female, and ~20%/28% fat on preserved lean mass) — never a 28% body-weight crash (e.g. 81 kg → 58.5 kg). When **build-muscle** is also selected, the cut is slower still and muscle in the table goes up. Caffeine timing is still asked because it grades lifestyle/sleep; default advice is stop 8 hours before bed. Fitness is **three inputs** — resting, peak, and recovery HR — plus a short coach protocol note (**no in-app timers**); protocol remains seated resting HR + a **4-min incline walk at 5 km/h, incline 10** + 1-min recovery → a **fitness score** (never labelled VO₂ max). Age/sex poor/average/good bands for those HR inputs live as **tooltips at entry**, not on the report. Coach-held posture on the assessment device must persist **in the same flow** — post-assessment manual upload is a failure, not a workflow — and must be **fast**: tap any view placeholder, shoot, move to the next while earlier views align in the background (never wait on one view before taking the next). Legacy `consultations` subcollection is read-only. Full plan is `buildStudioBaselinePlan()` (no P6); plan-wizard templates only after first completed full assessment; pre-assessment links via Resend (`emailRemoteIntakeLink`), never `mailto:`.
- Light/dark contrast is checked aggressively — avoid volt-green (brand) text on white/light backgrounds; every component must stay legible in both themes.
- Treat the user as a CLI/Firebase novice: when shell or migration steps are involved, walk through one command at a time, explain what each path/credential is, and do not assume placeholders will be resolved.
- For chat "thinking" UX, show short ephemeral status lines with loading dots (e.g., "Fetching X…", "Putting together a table…") that disappear before the final answer — never leave a residual list of steps in the message.
- Branding/copy must be wired through a single source so updates (PWA install prompt, notification bell, favicon, share artifacts, emails, landing page) propagate everywhere from one change.
- Prefer deterministic data-fetch flows over LLM calls whenever possible to control AI cost; lazy-inject only the client/assessment data the turn needs and cap conversation history.
- When a fix doesn't land after a couple of attempts, do a deep dive of the official docs (Context7 / vendor docs) before trying more variations.
- Current product focus is **add client → baseline assessment → AXIS report** for coaches. Hide or remove AI assistant/chat, milestones/achievements, shareable artifacts, and reassessment UI until that loop is solid; do not rebuild those surfaces unprompted. The **platform owner console** is a separate first-principles rebuild for the platform owner: a proper SaaS admin with charts (usage, revenue, users), per-organisation mini dashboards, and page navigation — not the old admin UI, and no AI. It lists **Organisations** typed **Coach** (buys for themselves and their clients) or **Gym** (buys for staff to use with members); never unnamed empty shells. Internal/house orgs (`isInternal`) show as **Free** with £0 revenue — leftover Stripe test billing must not mark them cancelled or paying.

## Learned Workspace Facts

- Stack: React 18 + Vite + TypeScript + Tailwind + shadcn/ui + Firebase (Firestore, Functions, Hosting, App Hosting) + MediaPipe + TanStack Query + Recharts. `.cursorrules` forbids `console.log` in committed code — always use the logger at `src/lib/utils/logger`. Root `tsconfig.json` is a solution file, so plain `tsc --noEmit` checks nothing — use `tsc --noEmit -p tsconfig.app.json`; vitest must exclude compiled `functions/lib/**`.
- User-facing brand is "One Assess" (the repo is `one-assess`); app is region- and currency-agnostic — GBP is the base, users transact in their local currency via Stripe + Wise multi-currency, the admin dashboard normalises to GBP with optional per-region drill-downs, and there must be no device-specific copy (no "iPhone", no "InBody").
- Brand vocabulary is user-facing only — never rename internal variables, Firestore fields, or scoring logic:
  - **AXIS Score™** (client-facing) = overall 0–100 rolling up five pillars.
