## Learned User Preferences

- Day-to-day work goes on the `develop` branch; the repo keeps only `main` and `develop`. Commit/push to `develop`, then merge to `main` for releases.
- Plan-first workflow: produce a written plan file, then execute it with the prompt "Implement the plan as specified, it is attached for your reference. Do NOT edit the plan file itself." Do not regenerate todos that the plan already created.
- After substantive UI/app changes, always finish by deploying with `npm run deploy:preview` and reply with the Hosting channel URL (the `…--preview-…web.app` link), not just the default site URL. Resend pre-assessment links use production `APP_HOST` (default `*.web.app`), not preview channels — run production hosting deploy when validating `/remote` for real clients.
- UI taste is minimalist and Claude-inspired: **clarity over cleverness** — the next move should always be obvious; push back on busy or “clever” UI. No boxes-in-boxes, no overlay paragraphs, restrained rounding, pill-shaped quick actions, full-bleed work surfaces. Computer-vision overlays (MediaPipe pose landmarks, etc.) must feel professional and trustworthy — restrained dot size and thin lines, never the heavy default look. **Client AXIS report** must be **presentable for a live post-assessment debrief**: professionally presented (InBody-like document feel), scannable, no placeholders or walls of text; every figure (hero, 12-week, tables, protein/macros) must come from **one calculation** and be explainable in the room — protein from **body weight**, not skeletal muscle; **goal-first** (findings secondary to the client’s stated goals — show we can get them there). The report is a **12-week aha** / no-obligation conversion tool: non-signups still keep the roadmap as a lead-magnet giveaway; joining clients reassess every 12 weeks. Drop decorative pillar graphics (body-comp bars, muscle maps, metabolic icons); keep a **filled radar** whose colour tracks the score (green high → amber → red low; not multi-coloured sides). Hero is **score left + radar right** plus a short **2–3 sentence** results summary underneath — no "Focus this block", not five competing sections. Pillar score badges use the same **traffic-light score colours** (not a colour per pillar). First assessments must **never** show "vs last" / "improved since last time" (re-saves of the same assessment are not a prior). Section bands use **alternating backgrounds**. **Posture** is image + feedback per view plus a short posture summary (not duplicated in Movement). **Lifestyle** is label + value + status chip (`LifestyleFactorsCard`, green/amber/red per factor) — **no alcohol row, no lifestyle icons** — not gap tables or long prose. **Movement** shows only patterns that need work — not three long lists or gap analysis. Measurable pillars can use current / 4-month / 12-month gap tables with goal-prioritized realistic progress. A compact **"Your 12-week roadmap"** (not 90-day) shows one deterministic behaviour card per assessed pillar — concrete habits (zone 2, protein each meal, caffeine 8h before bed, hit each body part twice a week), **never sets/reps**, no AI call — plus an achievable 12-week target body weight and macros and a soft CTA to work with the coach. The **self-guided takeaway** for non-signups is a compact 3-bullet habit block under the coached plan — never a second full plan. **Do not reference ARC** in the client report for now. Empty client surfaces must not show archetype or pillar scores before real assessment data. Healthy metrics outside the client’s goals should be congratulated or lightly maintained — not pushed to elite performance targets. Client/PWA copy stays plain-language (**Fitness level**, not raw VO₂/HRR). Coach daily loop is **assess → AXIS report**; push back on duplicate surfaces, pre-flight complexity, and anything that isn’t that loop. Remote pre-assessment welcome: one **Start** CTA, duration hint in brackets under the button, two short motivating lines — no numbered step lists or boxy landing chrome. Live movement capture on iPad: **observe-then-tag** chip pads (large targets, optional “looks good”, summary after the set) — not stacked dropdowns while the client is mid-rep.
- **New-client baseline:** **Pre-assessment** (P0 PAR-Q + P1 lifestyle/goals + optional posture) via coach link or in-studio; **physical assessment** in app (**P3 → P4 → P5 → P2 → P7**, `STUDIO_PHYSICAL_PHASE_ORDER` — fitness first for a true seated resting HR; P4 is gym-floor movement only; P5 strength; P2 is the private-room block last — analyzer, then tape + posture photos, immediately before Results). No in-app consultation product or booking funnel — consultations happen outside One Assess. **Walk-in studio:** P0/P1 in studio → physical order above. **Send link first** is the long-term main path: client prefills at home → studio shows **pre-assessment review only if partial** → physical (skip P0/P1 when remote complete; skip duplicate studio posture if four remote views set); coach picks up at fitness. **Entry flow:** every global "New assessment" button is new-client-only (name + email → straight into first capture step); existing-client reassessments start from the client profile, never the global buttons — but reassessment UI is deferred until the baseline assess-and-report loop is solid. Collect `clientGoals` on P1 + remote `full` scope; do **not** collect `goalDeadline` or pain severity. Track activity level (and steps), not primary training styles. Tape measurements are mandatory alongside analyzer body comp (keep shoulders and calves; **do not collect neck**) but **not mixed into body-comp scoring** — tape is for progress (“biceps grew, waist came in”). When **weight-loss** is a goal, AXIS year weight is floored at a healthy adult size (BMI ~21 male / ~20 female, and ~20%/28% fat on preserved lean mass) — never a 28% body-weight crash (e.g. 81 kg → 58.5 kg). When **build-muscle** is also selected, the cut is slower still and muscle in the table goes up. Caffeine timing is still asked because it grades lifestyle/sleep; default advice is stop 8 hours before bed. Fitness protocol is seated resting HR + a **3-min incline walk at speed 5 / incline 10** + 1-min recovery HR → a **fitness score** (never labelled VO₂ max); prefer the treadmill; in-app start/stop + 1-min recovery is optional. Age/sex poor/average/good bands for resting, peak, and recovery HR live as **tooltips on those assessment inputs at entry**, not on the report. Coach-held posture on the assessment device must persist **in the same flow** — post-assessment manual upload is a failure, not a workflow. Legacy `consultations` subcollection is read-only. Full plan is `buildStudioBaselinePlan()` (no P6); plan-wizard templates only after first completed full assessment; pre-assessment links via Resend (`emailRemoteIntakeLink`), never `mailto:`.
- Light/dark contrast is checked aggressively — avoid volt-green (brand) text on white/light backgrounds; every component must stay legible in both themes.
- Treat the user as a CLI/Firebase novice: when shell or migration steps are involved, walk through one command at a time, explain what each path/credential is, and do not assume placeholders will be resolved.
- For chat "thinking" UX, show short ephemeral status lines with loading dots (e.g., "Fetching X…", "Putting together a table…") that disappear before the final answer — never leave a residual list of steps in the message.
- Branding/copy must be wired through a single source so updates (PWA install prompt, notification bell, favicon, share artifacts, emails, landing page) propagate everywhere from one change.
- Prefer deterministic data-fetch flows over LLM calls whenever possible to control AI cost; lazy-inject only the client/assessment data the turn needs and cap conversation history.
- When a fix doesn't land after a couple of attempts, do a deep dive of the official docs (Context7 / vendor docs) before trying more variations.
- Current product focus is **add client → baseline assessment → AXIS report** only. Hide or remove AI assistant/chat, milestones/achievements, shareable artifacts, and reassessment UI until that loop is solid; do not rebuild those surfaces unprompted.

## Learned Workspace Facts

- Stack: React 18 + Vite + TypeScript + Tailwind + shadcn/ui + Firebase (Firestore, Functions, Hosting, App Hosting) + MediaPipe + TanStack Query + Recharts. `.cursorrules` forbids `console.log` in committed code — always use the logger at `src/lib/utils/logger`. Root `tsconfig.json` is a solution file, so plain `tsc --noEmit` checks nothing — use `tsc --noEmit -p tsconfig.app.json`; vitest must exclude compiled `functions/lib/**`.
- User-facing brand is "One Assess" (the repo is `fitness-flow-form`); app is region- and currency-agnostic — GBP is the base, users transact in their local currency via Stripe + Wise multi-currency, the admin dashboard normalises to GBP with optional per-region drill-downs, and there must be no device-specific copy (no "iPhone", no "InBody").
- Brand vocabulary is user-facing only — never rename internal variables, Firestore fields, or scoring logic:
  - **AXIS Score™** (client-facing) = overall 0–100 rolling up five pillars. Client report v2 (`buildClientReportModel`, `ClientReportV2Layout`): **goal-first** hero (**score left + radar right**, filled score-coloured radar; short **2–3 sentence** results summary; no "Focus this block") → pillar scorecard with **traffic-light score badges** (green/amber/red by score, not per-pillar colours; measurable pillars may show current / 4-month / 12-month gap tables) → compact **12-week roadmap** (deterministic per-pillar behaviour cards, `clientRoadmapCards.ts`, goal-priority order; achievable 12-week weight and macro targets; concrete habits, not sets/reps; compact 3-bullet **self-guided takeaway** for non-signups) → **Lifestyle** label + value + status chip (`LifestyleFactorsCard`; **no alcohol row, no icons**) nested in the lifestyle pillar → **Movement** needs-work patterns only (not three lists) → **Posture** image + feedback per view plus a short posture summary when captures exist (not repeated in Movement); **alternating section bands**; single-scroll; **no ARC teaser/references for now**. First assessments must not show "vs last" copy — `previousFormData` on public reports is often a same-assessment overwrite, not a prior assessment (`usePublicReport` ignores it). The post-save **coach debrief renders the exact same v2 document** the client sees; the public `/demo` marketing page intentionally keeps the legacy layout. Re-opens from saved `formData`/scores with **original assessment dates**; posture overlay images refresh only on **re-capture** or backfill. Cardio client line uses plain-language **Fitness level** (`calculateCardioAnalysis` — fixed inverted-HR submax inflation; never print an invented VO₂). 12-week protein from body weight, not SMM × 2.2. Hero / 12-week / gap tables must share one projection so they never disagree. Copy in `src/constants/clientReport.ts`.
  - **SIGNAL™ Report** (coach-facing only) = cross-pillar synthesis layer (priority themes, urgency, "what it means"); never surface in the client AXIS report.
  - **ARC™** (client-facing) = journey/roadmap with phases Foundation → Development → Performance; the system pre-fills a suggested ARC from the first full assessment's AXIS findings + client goals, the coach edits/confirms before sending; subsequent pillar assessments auto-update milestones; ARC completes when goals are hit, after which the next full assessment opens new goals — keep ARC off the AXIS report until explicitly re-enabled.
- **Assessments:** first baseline uses `buildStudioBaselinePlan()` (P0,P1,P3,P4,P5,P2,P7 — no P6) via `NewClientModal` (studio now or `remoteScope: 'full'` pre-assessment link). Coach sidebar groups **Pre-assessment** (P0,P1) vs **Physical assessment** (P2–P5,P7). `shouldShowStudioIntakeReview()` gates optional partial pre-assessment review only. Remote `/remote/:token` is mobile-first (one question per screen, choice cards not clipped selects); body comp in-studio (OCR must fail soft into fast manual entry — scan friction is a known studio pain). Analyzer printout and tape are both stored; scoring uses the analyzer, tape is progress-only. Body comp "Snap a Photo" opens the device camera **directly on every device** (the QR phone-companion modal is removed from body comp — routing tablets to it was the "scanner stopped working" regression); OCR apply never auto-advances, bad reads offer retake-or-manual, and kill-switch/credit blocks get distinct messaging. **Fitness (P3) is one flow**: resting HR is the first input of the section; age/sex HR bands via `CardioHrBandPopover` on resting/peak/recovery at entry; prefer treadmill clocks, with optional in-app start/stop + 1-min recovery via `CardioRunSheet`. Draft recovery keys on the saved **phase ID**, not index position, so phase reordering can't corrupt drafts. Remote submit sets `remoteIntakeAwaitingStudio`; overview CTA → start/continue physical assessment. Collect activity level (and steps), not `primaryTrainingStyles`; do not collect `goalDeadline` or pain severity. Caffeine timing is collected for lifestyle/sleep grading (advice: stop 8 hours before bed). **Movement:** P4 uses chip capture (`MovementPatternCapture`) for OHS/hinge/lunge; mobility sub-score derived via `deriveMobilityFromPatterns.ts` when legacy mobility fields empty (detail line: "Inferred from movement"; blank pattern fields mean **not observed**, never "good" — an empty form must not score 100); standalone mobility section removed from P4. Posture photos are a P2 section after tape (private room, last). Partial posture pillar mini-run defaults to posture section only. AXIS report **projected outlook** uses **4 / 12 month** (and related) horizons from baseline + `clientGoals`, extrapolated at goal-prioritized realistic rates (e.g. stated weekly loss/gain), not overly conservative under-projections. Overall AXIS Score™ only on full completion. Emailed intake URLs use Functions `APP_HOST` (production hosting); stale PWA/browser/iPad cache can show old UI until hard refresh.
- Coach product is trimmed to assess → AXIS report: AI assistant/chat, milestones/achievements, shareable artifacts, and reassessment entry points are hidden or removed until that loop is solid. Do not reintroduce those surfaces unprompted.
- Strict multi-tenancy: coaches see only their own clients; org admins get top-level org metrics (counts, capacity, coach activity) but never another coach's client-specific data. `coachUidFilter: null` = full org scope (admin & non-coaching admin); `coachUidFilter: undefined | uid` = own clients only — Firestore rules mirror this. Public client routes (`/r/:token`) are air-gapped from coach PII via dedicated `PublicReportViewer` / `PublicRoadmapViewer` components that read only public-safe paths.
- Posture: in-studio offers two visible options — **coach-held live capture** on the assessment device (`CoachPostureCapturePanel` + `PostureGuideOverlay` alignment guides for head/toes/vertical midline; UI prompts each view in order, coach shoots, judges quality, confirms or retakes; no voice/position detection) or the QR mobile handoff; DIY remote capture unchanged. Photos persist as **Storage URLs**, never base64 in the assessment document (Firestore 1MB cap caused Sync Error / empty filmstrips). After the last confirmed view, attach analysis and close — no separate Apply. Report overlay must **align the body to the grid** (`planPostureOverlay` / `drawAlignedImage`), using the same head/toes/midline guides as capture — never stamp a shoulders-25%/hips-50% template on a stretched photo. Gemini Live (`gemini-3.1-flash-live-preview`) remains the only voice when voice mode is used. `window.speechSynthesis` (Apple/browser TTS) must be hard-blocked in posture mode via `disableSpeechSynthesis: true` and `suppressAudioFeedback: true`. Live API is gated behind `VITE_ENABLE_GEMINI_LIVE`; voice configurable via `VITE_GEMINI_LIVE_VOICE_NAME`. When voice mode is on, walk the client through purpose → framing → per-pose countdown → close-out in plain language. Framing should stay comparable across sessions. Client photo uploads in HEIC/HEIF are converted server-side (Cloud Function) when browser conversion fails.
- Body-comp OCR uses `gemini-2.5-flash` via VertexAIBackend; pipeline is `downscaleBodyCompImage → runGeminiOcr → validate → return` (full downscaled frame — do not hard-crop, that cut the numbers off the printout). No learned-pattern or layout Firestore cache (that path could return another client’s values).
- Server-only operations (PDF, email/Resend, billing/Stripe, admin) live in Cloud Functions; when `firestore.rules`, any Cloud Function, or `executeClientErasure.ts` paired with `OrgOverview.tsx` change, deploy via `firebase deploy` — never hosting-only `deploy-preview.sh` for those.
- Client-facing surface is the AXIS report (vertical scroll with optional pillar jump row, not five pillar tabs). ARC and Milestones PWA tabs are deferred until the assess-and-report loop is solid.
- **Client delete:** Manage → Delete permanently requires typing the exact profile display name (title-cased `displayClientName`), not the URL slug — common after remote intake updates the name. Clients table bulk Delete = soft delete (30-day Trash). `remoteIntakeAwaitingStudio` does not block deletion. Dashboard Active/Today must honor client doc `status`; soft delete clears intake flags so deleted clients don't ghost on Today.
- Append-only analytics: every entity that contributes to analytics writes pre-computed summaries (`scoresSummary`, `categoryScores`, `pillarBreakdown`) at write time; new indexes go into `firestore.indexes.json` in the same PR.
